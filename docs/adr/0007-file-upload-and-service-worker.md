# ADR-0007: 파일 올리기는 그대로 두고, 서비스 워커는 한계로 기록한다
상태: 승인 · 날짜: 2026-11-14 · 작업: 20261114-agent-browser

## 맥락
검증 5회차는 PASS였다. 다만 사람이 정해야 할 항목 두 개가 남았다(`docs/verify/20261114-agent-browser.md`의 "사람 확인").
1. 에이전트가 `DOM.setFileInputFiles`로 로컬 파일을 페이지에 넣은 뒤, 묻지 않는 fetch로 밖에 보낼 수 있다.
2. 에이전트가 자기 탭에서 등록한 서비스 워커가 사람 탭의 같은 출처 응답을 바꿀 수 있다. 서비스 워커를 거친 POST는 폼 관문을 지나간다.

## 결정 (사람 결정 2026-11-14, 전달 단계 질문 창: "추천대로")
1. 파일 올리기는 막지 않는다. 막으면 도구의 `upload_file`·`setInputFiles`가 동작하지 않는다.
2. 서비스 워커는 막지 않는다. 알려진 한계로 `docs/spec.md` 위험 절에 적고 나중에 검토한다.

## 결과
- 코드는 바꾸지 않는다.
- 두 항목 모두 ADR-0004의 한계("에이전트가 사이트 안에서 한 행동")와 같은 성격이다. 앱의 승인 관문은 보조 장치이고 완전한 보장이 아니다.
- 나중에 막으려면 정책 허용 목록에서 `DOM.setFileInputFiles`를 빼거나, 에이전트 탭에서 `navigator.serviceWorker` 등록을 막는다. 둘 다 새 작업으로 계획한다.

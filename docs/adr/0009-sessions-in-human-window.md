# ADR-0009: 에이전트 세션을 창이 아니라 사람 창 안의 탭 묶음으로 둔다
상태: 승인 · 날짜: 2026-11-19 · 작업: 20261119-embedded-sessions

## 맥락
- 처음 설계(spec.md R1)는 세션마다 에이전트 창을 따로 띄웠다. 회사 PC에서 써 보니 오른쪽 패널의 세션 정보와 실제 브라우저 창이 따로 놀아, 어느 창이 어느 세션인지 알기 어려웠다.
- 사람이 고른 방향(2026-11-19, "권장 설계대로 해줘"): 창은 사람 창 하나뿐이고, 세션의 탭은 사람 창 안에서 패널로 골라 본다. 격리(R5·R6)와 관문(R12·R13)은 그대로 둔다.

## 결정
1. 세션 하나 = `TabStrip` 하나(`src/browser/agentSession.ts`). 사람 창(`humanWindow.ts`)의 내용 영역(주소창 아래, 패널 왼쪽)을 사람 탭과 함께 쓴다. 창을 만들지 않는다.
2. 왼쪽 화면에는 한 번에 하나만 보인다: 내 탭, 또는 패널에서 고른 세션(`viewing`). 세션을 보는 중에는 읽기 전용이다. 주소·이동·새 탭·닫기 명령은 화면에서 잠그고, main에서도 무시한다(E3). 탭 막대에서 보는 탭을 고르는 것은 되지만 에이전트의 활성 탭은 바꾸지 않는다(`display`).
3. **보이지 않는 세션도 계속 그린다(E4).** Chromium은 숨긴 view(`setVisible(false)`)와 다른 탭 view에 완전히 덮인 view를 그리지 않는다. 그러면 에이전트의 클릭(rAF 대기)과 `Page.captureScreenshot`이 멈춘다. 그래서:
   - 세션 탭은 `backgroundThrottling: false`로 만들고, 보이지 않는 세션의 활성 탭은 숨기지 않는다(`TabStrip.parkedView`).
   - 크기는 내용 영역 그대로 두고(에이전트가 보는 화면 크기가 바뀌지 않게) 창 오른쪽 아래 구석 바깥으로 비켜 둔다. k번째 탭은 왼쪽 위 1px만 창 안(x = 너비-1-k, y = 높이-1)에 들어오고, 나머지는 창 오른쪽·아래 바깥이라 보이지도 입력을 받지도 않는다. 더 왼쪽에 놓인 탭일수록 아래에 깔아 탭마다 자기 점이 드러나게 한다(`humanWindow.restack`). 진단용으로 `shownTab` 응답에 드러난 자리(`exposed`)와 창 크기(`content`)를 싣고, E4 시험이 점마다 1×1이고 창 오른쪽 아래 끝에 있는지 본다.
   - 드러나는 점이 페이지의 **왼쪽 위**여야 한다. 에이전트가 화면 크기를 줄이면(`emulate`, `setViewportSize`) 페이지는 view의 왼쪽 위에만 그려진다. 그래서 다른 점(왼쪽 아래 등)을 드러내면 그 점이 페이지 밖이 되어 다시 그리지 않는다(검증 2회차 중 compatExtended 5/5 실패로 확인).
   - 드러난 점은 덮지 않는다. 덮개 `View`를 얹어 봤더니 다시 그리지 않았다(Linux 시험 30장 중 14장 멈춤). `View`는 클릭도 막지 못한다(아래 view로 간다).
   - 창 내용 높이는 resize 이벤트 없이 줄 수 있다(Linux 메뉴 막대, 27px). 그러면 점이 창 밖으로 밀려나 그리기가 멈춘다(전체 파일 반복 실행에서 4/10 실패). 사람 창 UI 페이지는 자기 화면 크기(= 창 내용 크기)가 바뀌면 `resize`를 받으므로, 그때 `relayout` 명령으로 main에 알려 모든 탭을 다시 놓는다(사람 탭의 아래 27px이 잘리던 것도 함께 고쳐진다).
   - 검증 1회차 때는 창 오른쪽 위에 탭 위쪽을 맞춰, 패널 오른쪽에 세로 띠(폭 1px × 탭 높이)가 드러나 패널 스크롤바 위 클릭을 에이전트 탭으로 가져갔다. 지금 방식으로 고쳤다.
   - 세션 탭 묶음은 창 resize를 스스로 듣지 않고 사람 창이 한 번 받아 모두 다시 놓는다(세션마다 리스너가 쌓여 10개부터 경고가 나던 것).
   - 사람 탭은 비켜 두지 않는다(보이지 않는 사람 탭은 보통 브라우저의 뒤쪽 탭처럼 쉰다).
4. 세션 수 확인은 `listSessions`, 왼쪽 화면 확인은 `shownTab`(런처 ↔ 브라우저 ipc, 테스트용)으로 한다. `listWindows`는 사람 창 하나만 돌려준다.
5. 세션을 보던 중 그 세션이 끝나면(멈추기·붙이기 명령 끝남·앱 종료) 내 탭으로 돌아온다(E6).

## 결과
- 세션을 보는 중 "읽기 전용"은 주소·이동·새 탭·닫기 명령의 잠금이다. 보이는 세션 페이지 안의 클릭·키 입력은 막지 않는다(사람이 그 페이지의 링크를 누르면 에이전트의 탭이 이동한다. POST·다운로드는 관문을 거친다). 막을지는 사람이 정한다.
- 사람이 "A의 창을 닫는" 동작이 없어졌다. termination.spec.ts의 "R9: 사람이 A의 창을 닫아도 같다"는 "R9·E6: A를 보는 중 패널에서 멈추기를 눌러도 같고, 왼쪽은 내 탭으로 돌아간다"로 바꿨다. 패키지 시험(tests/dist/packaged.spec.ts) A3는 창 수 대신 browserUrl 응답으로 세션 끝남을 본다.
- 창 맨 아랫줄 오른쪽 끝에 보이지 않는 세션 수만큼 1px 점이 보일 수 있고, 그 점을 누르면 그 세션 탭의 왼쪽 위 끝에 클릭이 간다. 패널 너비(280px)보다 세션이 많으면 그 넘는 세션의 그리기는 보장하지 않는다.
- 보이지 않는 세션의 활성 탭도 계속 그리므로, 세션이 많으면 그만큼 CPU를 쓴다(예전 별도 창 때와 같다).
- macOS에서의 그리기 동작은 Linux(Xvfb) 시험으로만 확인했다. 회사 PC에서 `npm run test:dist`와 실제 사용으로 확인한다.
- 버린 대안:
  - 화면 밖(음수 좌표)에 완전히 두기: 그리지 않는다.
  - 창 위쪽 바깥에 두고 왼쪽 아래 점만 드러내기: 에이전트가 화면 크기를 줄이면 그 점이 페이지 밖이라 그리지 않는다.
  - 오른쪽 위에 두고 세로 띠를 `View`로 덮기: 그리기는 되지만 `View`가 클릭을 막지 못한다.
  - `webContents.incrementCapturerCount`: Electron 45에 없다.
  - 모든 세션 탭을 같은 자리에 겹치고 덮개로 가리기: 덮인 탭을 그리지 않는다.
  - Chromium 기능 끄기(`WebContentsOcclusion`, `ThrottleUndrawnFrames`, `OutputOcclusion`): 효과 없음.
  - 런처가 스크린샷 요청을 `fromSurface: false`로 바꾸기: CDP 정책을 바꾸게 되어 범위 밖이다.

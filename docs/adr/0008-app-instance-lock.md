# ADR-0008: 묶은 앱의 "이미 켜져 있나"는 런처 자물쇠 파일로 판단한다
상태: 승인 · 날짜: 2026-11-15 · 작업: 20261114-mac-app-package

## 맥락
- spec-mac-app.md P5: 앱이 켜진 상태에서 다시 열어도 런처·브라우저가 둘이 되면 안 된다.
- 1·2회차에서는 시작 프로세스가 Chromium 단일 인스턴스 자물쇠(`requestSingleInstanceLock`)로 실행 중인지 봤고, 런처를 띄우는 동안만 `starting.pid` 표시를 뒀다.
- 검증 2회차에서 연속 실행(8ms 간격 120회) 때 브라우저가 2~3개 뜨는 일이 재현됐다. Chromium 자물쇠는 잡고 있는 쪽이 바빠 응답이 늦으면 멈춘 것으로 보고 자물쇠를 가져간다. 그래서 시작 프로세스가 이 자물쇠를 건드리면 실행 중인 브라우저와 경쟁한다.
- 낡은 표시를 pid가 살아 있는지만으로 판정하면, 재부팅 뒤 pid가 다른 프로세스에 재사용됐을 때 앱이 열리지 않는다.

## 결정 (사람 결정 2026-11-15, 검증 2회차 뒤 질문 창: "A. 방식을 바꿔 고친다")
1. 프로필마다 런처 자물쇠 파일 `<프로필>/launcher.lock`을 둔다. 내용은 런처 pid다. 앱이 켜져 있는 동안 내내 유지하고, 런처가 끝날 때 지운다.
2. 자물쇠는 O_EXCL로 만든 쪽만 잡는다. 시작 프로세스가 잡으면 런처를 띄운다. `npm start`처럼 런처가 직접 시작하면 런처가 스스로 잡는다.
3. 자물쇠가 낡았다고 보는 경우는 둘이다.
   - pid가 없거나, 그 pid가 이 앱의 런처(`launcher/cli.js`)가 아니거나, 그 프로세스가 자물쇠에 pid가 적힌 뒤에 시작했을 때(다른 프로필의 런처가 pid를 재사용. 20261115-launcher-lock-race).
   - pid를 아직 적지 않은 채 10초가 지났을 때. pid는 런처가 SIGUSR2 처리기를 단 뒤 스스로 적는다(처리기 전에 신호를 받으면 기본 동작으로 꺼진다).
   낡은 자물쇠는 치우기 표시 `<자물쇠>.clearing`을 O_EXCL로 잡은 한 프로세스만 치운다. 표시를 잡은 뒤 다시 낡았는지 보고 지운 다음 새로 잡는다. 표시를 못 잡은 쪽은 물러난다(곧 주인이 생긴다). 10초 넘은 표시는 치운다.
   (처음 방식인 rename+inode 확인은 3개 이상이 동시에 치울 때 남이 새로 잡은 자물쇠를 지워 주인이 둘이 됐다. 20261115-launcher-lock-race)
4. 다시 열었을 때 자물쇠가 살아 있으면, 시작 프로세스는 런처에 SIGUSR2를 보내고 끝난다. 런처는 브라우저에 `focus`를 보내 사람 창을 앞으로 가져온다.
5. 시작 프로세스와 브라우저는 Chromium 단일 인스턴스 자물쇠를 쓰지 않는다. Dock이나 Finder로 다시 열면 macOS가 실행 중인 브라우저를 활성화하므로(`activate`) 그때도 사람 창을 앞으로 가져온다.

## 결과
- 한 프로필에 런처가 하나뿐이므로 브라우저도 하나뿐이다.
- 런처가 kill -9로 죽으면 자물쇠 파일이 남는다. 다음 실행이 pid를 보고 낡은 것으로 판정해 치운다.
- 버린 대안: Chromium 자물쇠를 브라우저에만 두는 방식. 시작 프로세스가 실행 중인지 묻는 길이 다시 Chromium 자물쇠가 되어, 같은 경쟁이 생긴다.

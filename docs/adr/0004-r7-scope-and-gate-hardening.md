# ADR-0004: R7을 "CDP 명령 단위"로 좁히고 페이지 세션을 허용 목록으로 거른다, 관문을 넓힌다
상태: 승인 · 날짜: 2026-11-14 · 작업: 20261114-agent-browser

## 맥락
- 검증 1·2회차에서 R7(공유 상태 보호)이 연속 FAIL이었다(docs/verify/20261114-agent-browser.md).
- 페이지 세션을 차단 목록으로 거르면 새 경로가 계속 나왔다. 1회차는 setCookie 만료, 2회차는 Fetch 응답의 Set-Cookie, ServiceWorker.unregister였다.
- 더 근본적으로, 로그인을 공유하는 설계에서는 에이전트가 어떤 사이트 안에서 하는 행동이 그 사이트의 공유 로그인을 바꿀 수 있다. 페이지 JS로 쿠키를 지우거나 로그아웃 버튼을 누르는 것이 그 예다.
- R13은 2회차에 "응답 전에 탭을 닫으면 출처를 모르는 다운로드를 사람 것으로 저장"하는 결함이 나왔다.

## 결정 (사람 결정 2026-11-14, 검증 2회차 뒤 질문 창)
1. **R7은 CDP 명령 단위로 본다.** 에이전트가 CDP 명령으로 다른 출처나 브라우저 전체의 상태(로그인·저장소·서비스 워커·보안 설정)를 지우거나 바꾸지 못하게 한다. 에이전트가 자기 탭으로 어떤 사이트 안에서 한 행동(페이지 JS, 그 사이트의 버튼)이 그 사이트의 로그인을 바꾸는 것은 막지 않고, spec의 알려진 한계로 적는다.
2. **페이지 세션 명령을 허용 목록으로 거른다.** 필요한 도메인과 메서드만 연다. 출처 사이에 걸치는 저장소 도메인(IndexedDB·DOMStorage·CacheStorage·Storage)은 읽기만 연다. ServiceWorker·Security 등은 막는다. Fetch의 가짜 응답·응답 이어 보내기에 Set-Cookie가 있으면 막는다(다른 출처의 쿠키를 응답으로 바꾸는 길).
3. **3회차에 함께 고친다(사람 승인):**
   - R13: 사람 창 탭으로 확인된 다운로드만 바로 저장하고, 출처를 모르는 다운로드는 막는다.
   - R12: iframe으로 보내는 POST(subFrame)도 관문에 넣는다. spec의 "최상위"보다 넓힌다.
   - code-review 2회차의 Major 경쟁 상황 3건과 다운로드 폴더가 없을 때의 처리도 고친다.

## 결과
- 쉬워지는 것: 모르는 새 CDP 명령은 기본으로 막히므로 우회가 계속 새지 않는다.
- 어려워지는 것: 도구가 새 도메인을 쓰면 막힐 수 있다. 막히면 E2E 호환 테스트(R4)가 알려 주고, 그때 허용 목록에 이유와 함께 더한다.

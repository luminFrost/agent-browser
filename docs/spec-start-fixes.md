# Spec: 앱 시작 결함 4건

사람 결정 (2026-11-15): 범위 "4건 모두", 실패 알림 "오류 창 + 기록", 규모·강도 "M, 보통"

## 가치
정리 5건 검증에서 후속으로 남긴 Minor 4건(`docs/verify/20261115-cleanup-five.md` "후속")을 고친다. 앱을 언제 다시 열어도 켜지거나, 못 켜면 이유를 알 수 있게 한다.

## 범위
- 한다: 아래 D1~D4. 시작 판단(`src/app/entry.ts`의 `start`·`waitAndStart`)을 Electron 없이 시험할 수 있는 모듈로 떼어 낸다(동작 변경과 다른 커밋).
- 안 한다: 서명·공증, 앱 동작(R1~R13) 변경, 새 라이브러리, 버전 번호 변경.

## 요구사항과 인수 사례 (= 완료 기준)
| # | 요구사항 | 인수 사례 (입력 → 기대 결과) | 확인 방법 |
|---|---|---|---|
| D1 | 꺼지는 순간 다시 열기 | (가) 자물쇠 잡기가 실패한 뒤 pid를 읽기 전에 자물쇠가 사라지면 → 다시 잡고 새 런처를 띄운다. (나) pid를 읽었는데 신호를 보낼 때 그 프로세스가 이미 없으면(ESRCH) → 오류로 끝나지 않고 자물쇠가 풀리기를 기다렸다가 새 런처를 띄운다 | 단위 테스트(자물쇠·신호를 흉내 내 두 경우를 그대로 만든다) |
| D2 | 다시 열 때 고정 대기 없앰 | 켜진 앱을 다시 열면 런처가 신호를 받았다는 표시(`<lock>.ack`)를 남기고, 시작 프로세스는 그 표시를 보는 즉시 끝난다. 표시가 오면 기다린 시간이 50ms 미만(흉내 낸 시계로 잼). 런처가 끄는 중이면 표시를 남기지 않는다. 표시가 300ms 안에 안 오면 지금처럼 끄는 중인지 다시 본다 | 단위 테스트 + 묶은 앱 E2E: 켜진 앱을 다시 열면 `.ack`가 생기고 창이 앞으로 옴(기존 P5 통과) |
| D3 | 15초 실패 알림 | 끄는 중인 런처를 15초 기다려도 새 런처를 못 띄우면 → 오류 창("앱이 아직 끄는 중입니다. 잠시 뒤 다시 열어 주세요" 취지)을 띄우고 `launcher.log`에 한 줄 남기고 종료 코드 1로 끝난다 | 단위 테스트(흉내 낸 시계로 15초 경과, 알림 함수 호출·기록·실패 결과 확인). 실제 오류 창 모양은 확인 대상 아님 |
| D4 | 기록 교체 실패해도 시작 | `launcher.log` 교체(이름 바꾸기)가 실패하면(예: `launcher.log.1` 자리에 비지 않은 폴더) → 오류 없이 지나가고 기존 파일에 이어 쓴다 | 단위 테스트 |

확인 방법(공통): `npm run lint`, `npm test`, `npm run build`, `npm run test:dist`가 모두 통과한다(정리 5건 C1 10회 다시 열기 포함, 기존 동작 유지).

## 위험
- 로컬 앱만 바뀐다. 되돌리기: main을 이 작업 전 커밋(61964e6)으로 되돌리고 `npm run dist`.

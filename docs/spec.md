# Spec: agent-browser (Electron + CDP 에이전트 공간 브라우저)
상태: 승인 · 작업: 20261114-agent-browser · 구분: 남길 것 · 정본: 이 문서 · 규모: L · 검증 강도: 엄격

## 가치
사내 보안 때문에 외부 AI 브라우저(Aside, Ego Lite 등)를 쓸 수 없는 개발자가, 직접 만든 브라우저에서 사람 창과 로그인을 공유하는 에이전트 전용 창을 써서, 여러 에이전트 세션이 동시에 브라우저를 조작할 수 있게 한다. 지금 쓰는 Claude in Chrome은 여러 세션에서 함께 쓰기 어렵다.
- 배경 1: 외부 AI 브라우저는 사내 보안 정책에 막혀 있다 → 사내에서 직접 만든다.
- 배경 2 (주 목적): Claude in Chrome은 여러 세션이 함께 쓰기 어렵다 → 세션마다 에이전트가 따로 붙을 수 있어야 한다.

## 범위
- 한다:
  - 사람 창: 주소창, 탭, 뒤로/앞으로/새로고침이 되는 최소 브라우저.
  - 에이전트 공간: 사람 창과 따로 있는 창. 사람 창과 같은 `persist:` 세션 파티션을 써서 로그인(쿠키·스토리지)을 공유한다.
  - 여러 세션: 에이전트 세션마다 자기 창(탭 묶음)을 따로 받는다. 다른 세션의 탭과 사람 창의 탭은 보이지 않고 조작할 수도 없다.
  - 붙는 방식: 세션마다 CDP WebSocket 엔드포인트를 연다. 앱이 CDP를 중계하면서 그 세션의 탭만 보이게 거르므로, chrome-devtools-mcp나 Playwright의 `connectOverCDP` 같은 기존 도구를 그대로 붙일 수 있다.
  - 지켜보기·멈추기: 사람 창에서 어떤 세션이 어떤 탭을 쓰고 있는지 보고, 세션을 멈출 수 있다.
  - 접속 보호: 제어 포트는 토큰이 있어야 쓸 수 있다. 세션 엔드포인트에는 추측하기 어려운 경로가 들어간다.
  - 승인 관문(보조 장치): 에이전트 창에서 일어나는 폼 제출(POST로 페이지·iframe 이동)과 다운로드는 사람 창에서 허용해야 진행된다. `fetch`나 XHR로 전송하는 경우는 걸러내지 못한다. 위험 판단은 기본적으로 에이전트 쪽이 하고, 이 관문은 그 보조다.
- 안 한다:
  - 브라우저 확장, 동기화, 북마크, 비밀번호 관리자
  - 앱 안에 AI 채팅이나 LLM 호출 넣기 (에이전트는 외부, 예: Claude Code)
  - 자동 업데이트, 코드 서명·공증, 배포 패키징 (다른 개발자 배포·오픈소스 공개는 이후. 단 설계가 막지 않게 한다)
  - 사람 창의 탭을 에이전트에게 넘겨주기
  - 원격 접속 (엔드포인트는 localhost에만 연다)

## 요구사항과 인수 사례 (= 완료 기준, 끝난 뒤 자동 판정)
| # | 요구사항 | 인수 사례 (입력 → 기대 결과) | 확인 방법 |
|---|---|---|---|
| R1 | 창 분리 | 앱 실행 → 사람 창 1개만 있다. 세션을 만들면 → 에이전트 창이 새로 1개 생긴다 | E2E (테스트가 `startApp`을 직접 띄움, ADR-0002) |
| R2 | 로그인 공유 | 사람 창에서 로컬 테스트 서버에 로그인 → 세션 A의 탭에서 같은 주소를 열면 로그인 상태다. 앱을 다시 켜도 유지된다 | E2E + 로컬 테스트 서버 |
| R3 | 세션 생성 | 토큰 파일(권한 0600)의 토큰을 붙여 `POST http://127.0.0.1:<제어포트>/sessions` → `{id, browserUrl}`을 받는다(세션마다 별도 포트, 경로에 세션 비밀값). browserUrl의 `/json/version`과 `/json/list`가 CDP 형식으로 응답한다 | 단위(Vitest) + E2E |
| R4 | 기존 도구 호환 | chrome-devtools-mcp를 `--browserUrl`로 붙여 navigate와 snapshot이 성공한다. Playwright의 `connectOverCDP`로 페이지를 열고 클릭할 수 있다 | E2E (chrome-devtools-mcp, Playwright) |
| R5 | 탭 격리 | 세션 A·B와 사람 창에 탭이 있다 → A의 `/json/list`와 `Target.getTargets`에는 A의 탭만 나온다. `Target.setDiscoverTargets` 이벤트에도 다른 탭이 나오지 않는다 | 단위 + E2E |
| R6 | 격리 우회 차단 | A가 B의 탭 targetId나 사람 창의 탭 targetId로 `attachToTarget` → 오류를 받는다. A의 `Target.createTarget`과 A의 탭에서 연 팝업(`window.open`) → A의 창에 생긴다 | 단위 + E2E |
| R7 | 공유 상태 보호 | A가 CDP 명령으로 브라우저 전체나 다른 출처의 상태를 지우거나 바꾸려 한다(`Browser.close`, `Network.clearBrowserCookies`, `Storage.clearDataForOrigin`, 쿠키 설정, `ServiceWorker.unregister`, Fetch 응답의 Set-Cookie 등) → 오류를 받고 사람의 로그인은 그대로다. 페이지 세션 명령은 허용 목록으로 거른다(ADR-0004) | 단위 + E2E |
| R8 | 동시 세션 | A와 B가 동시에 다른 주소로 navigate → 서로 영향이 없다 | E2E |
| R9 | 종료 | 사람이 세션 A를 멈추거나 A의 창을 닫는다 → A의 CDP 연결이 끊기고 A의 browserUrl은 더 이상 응답하지 않는다. B는 계속 동작한다 | E2E |
| R10 | 잘못된 접속 | 없는 세션이나 이미 끝난 세션의 엔드포인트에 접속 → 거부된다. 외부 인터페이스 IP로 접속 → 연결되지 않는다 (127.0.0.1에만 바인딩). 토큰 없이 또는 틀린 토큰으로 `POST /sessions` → 401. 세션 포트에 비밀 경로 없이 `/json/version` → 거부 | 단위 + E2E |
| R11 | 지켜보기 | 사람 창에 세션 목록과 각 세션의 탭 URL이 보이고, "멈추기" 버튼이 R9처럼 동작한다 | E2E (화면) + 상태별 스크린샷 |
| R12 | 폼 제출 관문 | 세션 A의 탭에서 로컬 테스트 서버의 폼을 제출(POST로 페이지 이동, iframe 안으로 보내는 POST 포함 — ADR-0004) → 요청이 서버에 닿기 전에 멈추고 사람 창에 "세션 A · 호스트 · 폼 제출 — 허용/거부"가 뜬다. 허용하면 서버가 요청을 받고, 거부하면 서버가 받지 않으며 A의 탭에는 차단 오류 페이지가 뜬다. GET 이동은 묻지 않는다 | E2E + 테스트 서버 요청 기록 |
| R13 | 다운로드 관문 | 세션 A의 탭에서 다운로드가 시작된다 → 사람 창에서 허용해야 저장된다. 거부하면 파일이 생기지 않는다. 사람 창의 다운로드는 묻지 않는다 | E2E |

## 제약
- 기술·환경: TypeScript + Electron(최신 안정판), Chrome DevTools Protocol.
- 플랫폼: macOS 전용. Windows는 써 보고 나서 이후에 검토한다(이번 범위에서는 확인하지 않는다).
- 도구(사람 승인): Vitest(단위), Playwright(`_electron` + `connectOverCDP`, E2E), chrome-devtools-mcp(R4 호환 확인), ESLint, tsc. 추가 승인(2026-11-14 수행 단계): `ws`(CDP 프록시의 WebSocket 서버, MIT), `typescript-eslint`(MIT).
- 확인 명령(수행 때 `.aif/config.yaml` `commands`에 넣는다): `test: npm test`, `lint: npm run lint`, `build: npm run build`.
- 화면 상태: 페이지 로딩 표시와 로드 실패 오류 페이지만 둔다. 세션 목록이 비어 있으면 "에이전트 세션 없음" 문구 하나만 띄운다. 오프라인 전용 화면은 만들지 않는다.
- 권한: 사이트가 카메라·위치·알림 권한을 요청하면 기본적으로 거부한다.
- 설정: 포트와 데이터 경로를 하드코딩하지 않는다(다른 사람의 기기에서도 쓸 수 있게).
- 라이선스: 의존성은 오픈소스 공개에 지장이 없는 라이선스만 쓴다(수행 때 확인).
- 보안: 사람 창의 탭은 CDP로 노출하지 않는다. 제어 포트는 토큰을 요구한다. 엔드포인트는 127.0.0.1에만 바인딩한다. 브라우저 전체에 영향을 주는 CDP 명령은 막는다(R7).

## 상한 (완료 기준이 아니다)
- 시간: 실작업 8시간 (재는 방법: 이벤트 간격 5분 이하만 합산)
- 토큰: 1,000만 (재는 방법: input+output+캐시 쓰기, 캐시 읽기 제외)

## 위험
- 실제 데이터·결제·인프라에 닿는가: 배포 인프라와 결제에는 닿지 않는다. 다만 실제 사내 계정으로 로그인한 세션을 에이전트에게 연다.
  - 같은 Mac의 다른 프로세스가 세션을 가로챌 수 있다 → 토큰 요구(R3·R10)로 대응한다.
  - 알려진 한계(ADR-0004): 에이전트가 자기 탭으로 어떤 사이트 안에서 한 행동(페이지 JS, 그 사이트의 로그아웃 버튼)은 그 사이트의 공유 로그인을 바꿀 수 있다. 앱은 CDP 명령으로 다른 출처나 브라우저 전체를 바꾸는 것만 막는다.
  - 에이전트가 실제 계정으로 하는 행동은 되돌릴 수 없다 → 에이전트 쪽 판단 + 앱의 승인 관문(R12·R13) + 지켜보기·멈추기(R11). 관문은 보조 장치이고 완전한 보장이 아니다.
  - 격리 약속(R5~R7)은 나중에 공개하면 외부에 하는 보안 약속이 된다 → 검증 강도를 엄격으로 둔다.
- 되돌리는 방법: 배포하지 않고 로컬 빌드로만 쓴다. 문제가 생기면 앱을 끄고 파티션 데이터(`userData`)를 지워 로그인 상태를 없앤다.

| ~~경로가 붙은 URL 호환~~ → **해결:** 두 도구 모두 경로를 지킨다(`docs/adr/0003-gates-and-secret-path.md`) | R3, R4, R10 | 해결 (T0 스파이크) |
| ~~POST·다운로드 붙잡기~~ → **해결:** POST는 `onBeforeRequest` 보류, 다운로드는 격리 폴더 후 이동/삭제(`docs/adr/0003-gates-and-secret-path.md`) | R12, R13 | 해결 (T0 스파이크) |

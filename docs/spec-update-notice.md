# Spec: 앱 안 업데이트 알림과 한 번 눌러 업데이트
상태: 승인 (2026-11-23 14:55, 사람: "둘 다 진행해" — 제안 ①v0.2.4 Release ②앱 안 업데이트 알림) · 구분: 남길 것 · 정본: 이 문서 (앱 동작은 `docs/spec.md`, 설치는 `docs/spec-company-setup.md`·`docs/setup.md`) · 규모: M · 검증 강도: 보통 · 작업: 20261123-update-notice
사람 지적 (2026-11-23 14:47): "설치는 내가 했으니 … 이렇게 불편하면 사용안하지" — 개인 Mac에 0.1.0(11/15)만 남아 있었고, 새 버전이 나와도 앱이 알려 주지 않아 사람이 직접 확인·설치했다.

## 가치
새 Release가 나오면 앱이 패널에 알리고, 버튼 하나로 받기·바꾸기·다시 켜기까지 한다. 사람은 버전을 확인하거나 설치 명령을 칠 필요가 없다. 이번 v0.2.4 설치가 마지막 수동 설치가 된다.

## 범위
- 한다
  - 묶은 앱이 켜질 때와 6시간마다 GitHub의 최신 Release를 묻는다(GET, 인증 없음). 새 버전이면 패널 맨 위에 알림 줄과 **업데이트** 버튼.
  - **업데이트**: 그 버전의 dmg를 임시 폴더에 받고, 앱이 끝난 뒤 같은 자리의 앱을 새것으로 바꾸고 다시 여는 설치 스크립트(`resources/update-mac.sh`)를 띄운 뒤 앱을 끈다.
  - 끄기 설정: 프로필 `settings.json`의 `"updateCheck": false`(Dock·Finder로 켠 앱에도 닿음, 검증 2회차) 또는 환경 변수 `AGENT_BROWSER_UPDATE_CHECK=off`면 묻지 않는다.
  - v0.2.4: 버전, 회사 PC 확인표에 이번 확인 항목, README·setup.md.
- 안 한다
  - 자동으로 깔기(사람이 버튼을 누를 때만 바꾼다. 앱이 다시 켜지면 에이전트 세션이 끊기기 때문)
  - 서명·공증, 델타 업데이트, 되돌리기 메뉴
  - 개발 실행(`npm start`)에서 묻기(묶은 앱만. 시험은 `AGENT_BROWSER_UPDATE_URL`로 켠다)
  - Claude Code MCP 다시 등록(앱 경로가 같아 필요 없다)

## 요구사항과 인수 사례 (= 완료 기준)
| # | 요구사항 | 인수 사례 (입력 → 기대 결과) | 확인 방법 |
|---|---|---|---|
| U1 | 새 버전 알림 | 최신 Release가 지금보다 높다(태그 `v9.9.9`, 자산 `Agent-Browser-9.9.9-arm64.dmg`) → 패널 맨 위에 "새 버전 9.9.9"와 **업데이트** 버튼. 같거나 낮은 버전, 응답 실패(연결 거부·HTTP 오류·JSON 아님), 그 버전의 dmg 자산 없음 → 아무것도 보이지 않고 앱은 그대로. `settings.json` `"updateCheck": false` 또는 `AGENT_BROWSER_UPDATE_CHECK=off` → 묻지도 않는다. 다시 묻는 간격은 6시간 | 단위(버전 비교·응답 해석) + E2E(시험 서버, 고치기 전 실패) |
| U2 | 받고 넘기고 끄기 | **업데이트** → 줄이 "받는 중…"이 되고 dmg를 임시 폴더에 받는다(받은 파일 = 서버가 준 내용) → 설치 스크립트를 `dmg 경로, 앱 경로, 앱 pid` 인자로 떨어진 프로세스로 띄운다 → 앱이 끝난다. 받기 실패(HTTP 오류)면 줄에 "업데이트 실패: 이유"와 **업데이트** 버튼이 다시 보이고 앱은 계속 돈다 | E2E(가짜 설치 스크립트로 인자·파일 확인, 고치기 전 실패) |
| U3 | 설치 스크립트 | `update-mac.sh <dmg> <앱> <pid>`: pid가 끝나길 기다린 뒤(최대 30초) dmg를 붙여 안의 `.app`을 같은 자리에 바꿔 넣고 dmg를 떼고 새 앱을 연다. 복사가 실패하면 원래 앱을 되돌리고 0이 아닌 코드로 끝난다. 앱이 끝난 뒤의 실패면 원래 앱을 다시 연다(사람이 앱 없이 남지 않게, 검증 1회차 지적). 앱이 끝나지 않으면 아무것도 바꾸지 않는다. dmg는 성공·실패 모두 뗀다. 기록은 프로필의 `update.log` | 단위(`hdiutil`·`ditto`·`open`을 가짜 명령으로 바꿔 돌림, Linux·macOS) |
| U4 | v0.2.4 문서 | `package.json`·lock 0.2.4, 회사 PC 확인표 v0.2.4(화면 모드·업데이트 버튼·v0.2.3 모름 항목), README·setup.md에 앱 안 업데이트 설명, ADR-0010(GitHub에 묻는 결정) | 단위(확인표·문서 시험) |

## 제약
- 원본 CDP는 런처만, TCP 디버그 포트 없음(ADR-0002). 이 작업은 브라우저 main의 HTTP GET과 파일 받기만 더한다.
- 하드코딩 URL 금지: Release 주소는 `package.json`의 `repository`에서 만든다. 시험은 `AGENT_BROWSER_UPDATE_URL`.
- 시험을 끄거나 지우지 않는다. 런처·앱 연결 코드를 바꾸면 E2E부터(I-015).
- 회사 밖으로 보내는 것: GitHub에 버전 조회 GET 한 번(앱 데이터 없음). ADR-0010에 근거와 끄는 법.

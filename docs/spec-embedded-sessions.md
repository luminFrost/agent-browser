# Spec: 에이전트 세션을 사람 창 안에서 보기
상태: 승인 (2026-11-19) · 구분: 남길 것 · 정본: 이 문서 (앱 동작 전체는 `docs/spec.md`, 이 문서가 R1·R9·R11을 바꾼다) · 규모: M · 검증 강도: 엄격 · 작업: 20261119-embedded-sessions
사람 결정 (2026-11-19):
- 회사 PC에서 써 보니 세션마다 별도 창이 떠서 "세션 정보(사람 창 오른쪽 패널)"와 "실제로 움직이는 브라우저"가 따로 논다.
- 권장안 채택: 에이전트 세션의 탭을 사람 창 안에서 보여 주고, 별도 창은 띄우지 않는다. 에이전트는 지금처럼 자기 탭만 다룬다(격리 유지).

## 가치
사람은 창 하나만 띄워 두고, 오른쪽 패널에서 세션을 누르면 왼쪽 화면에서 그 에이전트가 지금 무엇을 하는지 바로 본다. 창이 세션 수만큼 늘어나지 않고, 세션 정보와 실제 화면이 한곳에 붙어 있다.

## 범위
- 한다
  - 세션을 만들어도 OS 창을 새로 띄우지 않는다. 세션의 탭(WebContentsView)은 사람 창 안에 두고 보일 때만 화면에 나온다.
  - 사람 창에 "보기 대상"이 있다: 내 탭(기본) 또는 세션 하나. 패널에서 세션을 누르면 왼쪽 영역·탭 막대·주소창이 그 세션 것으로 바뀐다.
  - 세션을 보는 동안 주소창·뒤로/앞으로/새로고침/새 탭은 잠긴다(읽기 전용). 머리에 "세션 ○○ 보는 중 · 내 탭으로" 표시가 붙는다. 탭 막대에서 그 세션의 탭을 눌러 보는 탭을 바꿀 수는 있다(에이전트의 활성 탭은 바꾸지 않는다).
  - 에이전트는 화면에 보이지 않는(다른 세션이나 내 탭을 보는) 동안에도 지금처럼 동작한다.
  - Claude에게 주는 MCP 안내, `README.md`, `docs/setup.md`의 "세션 전용 창" 문구를 새 동작에 맞게 고친다.
  - 결정을 `docs/adr/0009-sessions-in-human-window.md`로 남기고 `docs/spec.md`의 R1·R9·R11에 이 문서를 가리키는 줄을 단다.
- 안 한다
  - 사람 탭을 에이전트에게 넘기기, 에이전트 탭을 사람 탭으로 옮기기
  - 여러 세션을 한 화면에 나란히(분할) 보기
  - 별도 에이전트 창을 고를 수 있는 옵션 남기기
  - CDP 중계·격리 규칙(policy, scope, router) 변경, 새 라이브러리
  - Windows 확인, 서명·배포

## 요구사항과 인수 사례 (= 완료 기준)
| # | 요구사항 | 인수 사례 (입력 → 기대 결과) | 확인 방법 |
|---|---|---|---|
| E1 | 창 하나 | 앱 실행 후 세션 A·B를 만든다 → OS 창은 사람 창 1개뿐이고, 패널에 A·B가 보인다. 세션 목록 조회에 A·B가 있다 | E2E (`listWindows`·세션 목록) |
| E2 | 세션 보기 | 패널에서 A를 누른다 → 왼쪽 영역에 A의 활성 탭이 보이고, 탭 막대는 A의 탭, 주소창은 A의 탭 주소(읽기 전용), 머리에 "세션 A 보는 중"이 있다. A가 CDP로 다른 주소로 이동하면 화면과 주소창이 따라 바뀐다. "내 탭으로"를 누르면 사람 탭이 원래 상태로 다시 보인다 | E2E (화면) + 상태별 스크린샷 |
| E3 | 사람 조작과 분리 | A를 보는 중 → 주소창·뒤로·새 탭이 잠겨 있다(입력해도 A의 탭은 이동하지 않는다). 내 탭으로 돌아오면 사람 탭의 주소·기록이 그대로다 | E2E |
| E4 | 보이지 않아도 동작 | 사람이 내 탭이나 B를 보는 동안 → A에 붙은 chrome-devtools-mcp의 navigate·snapshot·screenshot과 Playwright `connectOverCDP`의 클릭이 성공한다 | E2E (기존 R4·A1 + 숨김 상태) |
| E5 | 격리 유지 | 같은 창에 들어와도 R5·R6·R7·R12·R13이 그대로다: A의 `/json/list`·`getTargets`에 사람 탭·B 탭이 없고, 사람 탭 다운로드는 묻지 않으며, A 탭의 폼 제출·다운로드는 묻는다 | 기존 단위·E2E 전부 통과 |
| E6 | 종료 | 패널에서 A를 멈추기 → A가 패널에서 사라지고 A의 browserUrl은 응답하지 않는다. A를 보던 중이었다면 내 탭으로 돌아간다. 붙이기 명령(MCP)이 끝나면 5초 안에 A가 패널에서 사라진다. B는 계속 동작한다 | E2E (기존 R9·A3 갱신) |
| E7 | 빈 상태 | 세션이 없으면 패널에 "에이전트 세션 없음"만 있다. 보고 있는 세션의 탭이 모두 닫히면 왼쪽에 "이 세션에 열린 탭이 없습니다"가 보인다 | E2E + 스크린샷 |
| E8 | 안내 문구 | MCP 안내(`AGENT_BROWSER_GUIDE`)·README·setup.md에 "세션 전용 창" 대신 "사람 창 안의 세션 화면"으로 설명되어 있고, 창을 닫는 대신 패널의 멈추기로 끝난다고 적혀 있다 | 단위(문구 테스트) + 원문 확인 |

## 확인 방법
- `npm test`(build → Vitest → Playwright E2E), `npm run lint`, `npm run build`. 이 클라우드 작업 공간(Linux)에서는 `xvfb-run`으로 돌린다.
- 상태별 스크린샷: 내 탭 / 세션 보기 / 세션에 탭 없음 / 세션 없음.
- 확인 못 하는 것: macOS 묶은 앱(`npm run test:dist`)과 실제 회사 PC 동작은 사람이 Mac에서 확인한다.

## 검증 강도
엄격. 같은 창 안에 사람 탭과 에이전트 탭이 함께 있게 되어 격리 약속(R5~R7)과 관문(R12·R13)에 닿는다. 검증은 reviewer(이 문서 대조) + code-review(새 서브에이전트 diff 검토).

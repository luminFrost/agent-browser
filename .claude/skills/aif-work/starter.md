# 개발 스타터: 수행 (개발)

## 표준
1. **작업 목록:** `docs/tasks.md`에 작업을 쪼갠다(양식 `.aif/framework/templates/tasks.md`). 작업마다 다음을 적는다.
   - 바꿀 파일
   - 대응하는 인수 사례
   - 확인 명령

   작업 하나는 리뷰할 수 있는 크기로 한다.
2. **작업 하나씩** 진행한다.
   1. 인수 사례로 실패하는 테스트를 쓰고, 실패하는 것을 실행해서 보인다.
   2. 통과시키는 최소 구현을 한다.
   3. 확인 명령을 실행한다.
   4. 정리하고 커밋한다.
   5. `tasks.md`에 체크한다.
3. 구조 변경(리팩터링)과 동작 변경은 다른 커밋으로 나눈다.
4. 기존 패턴을 먼저 찾아서 따른다. 새 의존성은 묻고 추가한다.
5. **세션을 나눈다.** 작업이 여러 개면, 작업 몇 개마다 `docs/progress.md`를 갱신한다. 맥락이 넘칠 것 같으면 새 세션으로 넘긴다.

## S
카드의 완료 기준으로 실패하는 테스트를 먼저 쓴다. 테스트로 표현할 수 없는 것(문구, 스타일)은 확인 절차로 대신한다. 그다음 구현하고 커밋한다.

## 탐색
테스트를 생략해도 된다. 대신 결과를 남기지 않는 브랜치·폴더에서 한다. 끝나면 배운 것과 "남길 것으로 만들려면 필요한 것"을 `docs/progress.md`에 쓴다.

## 막는 것 (훅이 강제)
- 테스트 파일 삭제, skip·only 추가: Stop 훅이 막는다. 정말 필요하면 이유를 대고 사람에게 묻는다.
- main·master로 push, 강제 push: PreToolUse 훅이 막는다.

## 순서 (고정)

1. `node .aif/framework/bin/aif.mjs task phase verify`를 실행한다.
2. 목표 문서·카드에서 **완료 기준 목록**, **규모**(`.aif/current.json`의 size), **검증 강도**를 뽑는다(강도가 없으면 S는 `가볍게`, M·L은 `보통`).
3. **규모와 강도에 맞는 깊이로 검증한다.** 위험·크기에 비례하지 않는 검증은 효율을 해친다.

   | | 가볍게·보통 | 엄격이면 더할 것 |
   |---|---|---|
   | **S** | 이 세션에서 확인 방법(명령·원문 대조)을 실행하고 그 출력이 증거 | `/code-review`, 사람 확인 항목 |
   | **M** | 확인 명령 + `reviewer` 한 명(목표 문서 경로와 변경 범위만 넘김) | `/code-review`, 사람 확인 항목 |
   | **L** | 설정의 `verifier` 전부(`code-review`, `verify`, `reviewer`) + 스타터의 테스트 품질(핵심 로직) | 테스트 품질 변경 전체, 되돌리기 확인 |

   - 검증자는 수행 과정을 보지 않은 상태여야 한다.
   - 완료 기준이 직접 요구하지 않는 측정(픽셀 색 세기, 전수 측정, 성능 측정)은 하지 않는다.
   - 자동 수정 횟수: S 1회, M·L 2회(설정 `limits.auto_fix_rounds`가 있으면 그것).
4. **기준마다 PASS / FAIL / 확인 못 함 중 하나를 붙이고 증거를 붙인다.**
   - 증거는 명령 출력, 파일·줄, 원문 인용, 스크린샷 경로처럼 다시 볼 수 있는 것이어야 한다.
   - 증거가 없으면 PASS가 아니다.
   - 확인할 수단이 없으면 "확인 못 함"과 이유를 쓴다.
5. 스타터 구현의 추가 검증을 한다.
6. **결과를 쓴다.** S는 카드 아래 기준별 한 줄 표, M은 짧은 표(기준·판정·증거), L은 스타터의 검증 보고 양식.
7. **게이트**
   - 전부 PASS면 `node .aif/framework/bin/aif.mjs task gate verify pass --evidence <보고 경로>`.
   - FAIL이 있으면 `... gate verify fail ...`을 실행한다.
8. **FAIL 뒤 자동 수정 (사람을 기다리지 않는다)**
   - 이 작업의 `gate verify fail` 횟수(`.aif/tasks/<ID>/events.jsonl`)가 규모별 자동 수정 횟수 이하이면 바로 이어서 한다.
     1. `node .aif/framework/bin/aif.mjs task phase work`
     2. FAIL 항목마다 **그 결함을 잡는 테스트를 먼저** 고치거나 추가하고(실패 확인), 구현을 고치고, 확인 명령을 돌리고, 커밋한다.
     3. "확인 못 함" 중 이 세션에서 증거를 만들 수 있는 것(화면 캡처, 명령 출력)은 만든다. 사람만 정할 수 있는 것(기준이 틀림, 외부 접근 필요)은 남긴다.
     4. 1번부터 다시 검증한다. 검증자는 **새로** 부른다. 앞의 검증자 결과나 수정 과정을 넘기지 않는다.
   - 횟수를 넘었거나, 같은 항목이 두 번 연속 FAIL이면 멈춘다. 무엇이 왜 안 고쳐지는지(기준 문제·설계 문제·정보 부족)를 보고하고 사람의 결정을 받는다.
   - 사람이 정할 "확인 못 함"만 남고 나머지가 PASS면, 그 항목과 선택지를 보이고 결정을 받는다.
9. 전부 PASS가 되면 바뀐 것을 세 줄로 요약하고 "`/aif-deliver`로 전달한다"고 안내한다. 전달은 사람 승인 지점이라 여기서 멈춘다.

## 판정 대상
- 게이트는 **완료 기준과 제약만** 본다.
- **상한(시간·토큰)은 판정하지 않는다.** 넘었으면 보고에 적고 사람에게 알린다. 다 쓴 시간은 되돌릴 수 없어 FAIL로 두면 영영 통과하지 못한다.
- **검증자의 품질 지적:** 이번 변경 안의 Critical·Major는 FAIL로 다룬다. Minor·Low와 이번 변경 밖의 지적은 FAIL이 아니다. 보고의 "후속" 표에 남기고 고칠지는 사람이 정한다. 고칠 때마다 새 지적이 나오며 끝나지 않는 일을 막는다.

## 하지 않는 것
- 수행한 쪽의 "됐다"는 말을 증거로 쓰지 않는다.
- **이전 회차의 증거(스크린샷·출력)를 다시 쓰지 않는다.** 판정하는 커밋에서 새로 만든다. 증거마다 만든 커밋을 적는다.
- 참조 구현·기존 도구와 일치하는 것을 정답의 증거로 쓰지 않는다.
- 기준을 판정하기 쉽게 바꾸지 않는다. 기준이 틀렸으면 사람에게 알린다.

# 개발 스타터: 전달 (배포)

0. **기준 브랜치와 리모트를 먼저 확인한다.** 기준 브랜치는 `git symbolic-ref refs/remotes/origin/HEAD`, 없으면 로컬에 있는 `main`·`master` 중 하나다. 이름을 짐작해 `main..HEAD`를 쓰지 않는다. 리모트가 없으면 아래 "S·M (직접 병합)"처럼 커밋까지 하고, 병합 방법을 사람에게 묻는다.
   - 프레임워크 업데이트로 바뀐 `.aif/framework/`·`.claude/skills/aif-*` 파일이 커밋되지 않았으면, 이번 작업 변경과 섞지 말고 따로 커밋할지 사람에게 묻는다.
1. 작업 브랜치를 push한다. main·master로는 push하지 않는다(훅이 막는다).
2. PR을 연다.
   - 본문: 목표 문서 링크, 검증 보고 링크, 되돌리는 방법
   - 커밋에는 `Task: <ID>` 트레일러가 있어야 한다.
3. 사람이 리뷰하고 병합한다. 배포는 CI가 한다. 에이전트는 운영 자격 증명을 쓰지 않는다.
4. 배포 뒤 스모크 확인을 한다. 변형 파일의 "전달에서 할 것"을 따른다. 결과를 `docs/progress.md`에 남긴다.
5. 운영 데이터를 바꾸는 작업이면 병합 전에 백업과 복원 확인을 사람에게 요청한다.

## S·M (직접 병합)
PR 없이 기본 브랜치에 바로 넣는 프로젝트라면, 사람이 diff를 확인하고 직접 병합·push한다. 에이전트는 커밋까지만 한다.

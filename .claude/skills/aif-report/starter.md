# 개발 스타터: 원인 판정 추가 예시

| 원인 단계 | 개발에서의 예 |
|---|---|
| 기획 누락 | 인수 사례에 없던 경계·오류 상황이 검증이나 배포 뒤에 나옴. 화면 상태(빈·오류)가 spec에 없었음 |
| 의사결정 지연·번복 | 라이브러리·구조를 수행 중에 바꿈. 승인 뒤 범위가 늘어남 |
| 설정 문제 | 확인 명령이 비어 있어 검증을 못 함. 경로 규칙이 없어 역할 규칙이 안 읽힘. 테스트 지킴이가 막을 것을 못 막음 |
| 진행 방식 | 작업 하나가 너무 커서 상한을 넘거나 수정 요청이 반복됨. 테스트보다 구현을 먼저 함. 작은 규모로 시작했다가 올림, 규모 기대를 넘음. (맥락 압축 횟수는 참고만 한다. 지금 모델은 맥락이 1M이고 압축이 자동이라 크기 신호로 약하다) |
| 구현 | 타입·로직 실수, 기존 패턴 무시, 보안 실수 |

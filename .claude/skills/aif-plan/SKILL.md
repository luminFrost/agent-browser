## 순서 (고정)

1. **규모와 검증 강도를 제안한다.** 요청을 읽고 이유를 한 줄씩 쓴다. 기준은 `core` 규모 표와 스타터 구현의 예시다.
   - 규모: `탐색` / `S`(간단) / `M`(보통) / `L`(복잡). **애매하면 작은 쪽을 고른다.** 수행 중 넘으면 올리면 된다. 절차가 일을 앞지르지 않게 한다.
   - S는 모두 참일 때: 한두 문장으로 말할 수 있다, 되돌리기 어려운 결정(구조·데이터 모델·공개 계약·삭제)이 없다, 확인 방법이 있다, 스타터의 S 예시 크기다.
   - 검증 강도: `가볍게`(나만 씀·로컬·되돌리기 쉬움) / `보통`(다른 사람이 씀·데이터를 바꿈) / `엄격`(운영·결제·인프라·공개 계약·보안).
   - 설정 `budgets`의 기대 시간·토큰을 함께 보인다.
   - 사람이 확인하면 다음으로 간다. 질문 하나로 같이 묻는다.
2. **작업을 연다.** `node .aif/framework/bin/aif.mjs task new <짧은-영문-slug> --size <explore|S|M|L>`를 실행하고, 출력된 작업 ID를 이후 산출물에 적는다.
3. **규모별로 목표를 만든다.** 쌓인 질문(`.aif/plan-questions.md`) 중 이 작업에 해당하는 것만 넣는다.
   - **탐색:** 상한과 끝나는 조건을 `.aif/tasks/<ID>/card.md`에 적는다. 승인 없이 바로 수행한다.
   - **S:** `.aif/tasks/<ID>/card.md`에 목표 한 줄, 완료 기준 1~3개, 확인 방법, 검증 강도를 쓴다. 요청에 빠진 것이 결과를 바꿀 때만 하나 묻는다.
   - **M:** 스타터의 목표 문서에 가치·범위·완료 기준·확인 방법·검증 강도만 채운다. 나머지 칸은 필요할 때만. 빠진 칸만 묻되 3개까지.
   - **L:** 스타터의 목표 문서를 채우고, 빠진 칸을 인터뷰 순서대로 한 번에 하나씩 묻는다. 추정인 항목은 "확인 필요"로 표시한다.
   - **사람이 정하지 않은 품질 기준을 넣지 않는다.** 변형의 "기획에서 물을 것"은 M·L에서 묻기만 하고, 사람이 답한 것만 제약에 적는다. S에서는 묻지 않는다.
4. **이해한 것을 되돌려 말한다.** 목표, 완료 기준, 안 할 것, 규모·기대 시간, 검증 강도를 다섯 줄 이내로 보이고 고칠 곳을 묻는다.
5. **승인을 받는다.** 사람이 승인하면 카드·문서 맨 위 상태를 `승인`으로 바꾸고 `node .aif/framework/bin/aif.mjs task gate plan pass --evidence <경로>`를 실행한다. 사람이 승인하지 않았으면 상태를 바꾸지 않는다.
6. **이어서 진행한다.**
   - **S·M·탐색:** 사람을 기다리지 않고 바로 `aif-work` 스킬을 불러 수행한다.
   - **L:** "새 세션에서 `/aif-work`"라고 안내하고 멈춘다.

## 하지 않는 것
- 승인 전에 결과물(코드·보고서)을 만들지 않는다.
- "확인 필요"가 남아 있고 그것이 수행을 막으면 승인을 요청하지 않는다.
- 사람이 하지 않은 승인을 기록하지 않는다.
